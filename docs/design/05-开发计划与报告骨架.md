## 3. Git 提交规范与过程留痕

```
feat(core):     新功能

test:           测试
refactor:       重构
perf:           性能优化
style:          格式调整
chore:          构建/依赖
```

**要求**：
- 每日至少 2 次有意义的提交，**禁止**攒到最后一次性提交
- 提交信息用中文描述具体内容，避免 `update`、`fix bug` 这类无信息量的文字
- 答辩时用 `git log --graph --oneline` 或 GitHub 贡献热力图展示过程

```markdown
## 遇到的问题与解决
### 问题：JSqlParser 无法解析 MySQL 内联注释 /*!50000UNION*/
- 现象：抛出 JSQLParserException
- 分析：JSqlParser 默认按标准 SQL 解析，不识别 MySQL 方言的可执行注释
- 解决：在归一化阶段前置处理，将 /*!xxxxx内容*/ 还原为「内容」后再送入解析器
- 收获：认识到"预处理与解析器能力边界"的关系，方言差异是 SQL 安全工具的普遍难点

## 明日计划
- ……

## 工时统计
- 编码 5h / 调试 1.5h / 文档 1h
```

> **问题与解决**这一节是日志的价值所在，直接对应评分表"独立工作能力"与报告中的"技术难点"章节。务必如实记录真实踩过的坑。

## 5. 参考文献建议方向

为达到"具备国际视野、了解本专业领域国际前沿"（毕业要求 10-3），参考文献需含高质量英文来源：

1. OWASP Foundation. *OWASP Top 10:2021*
2. OWASP Foundation. *OWASP ModSecurity Core Rule Set Documentation*
3. Nick Galbreath. *libinjection: A C library for SQLi/XSS detection*（词法状态机方案）
4. Halfond W. et al. *A Classification of SQL Injection Attacks and Countermeasures*
5. Boyd S., Keromytis A. *SQLrand: Preventing SQL Injection Attacks*
6. Buehrer G. et al. *Using Parse Tree Validation to Prevent SQL Injection Attacks*
   ★ **这篇是本方案最直接的理论支撑，必引**
7. Zhang K., Shasha D. *Simple Fast Algorithms for the Editing Distance Between Trees*
8. Gartner. *Runtime Application Self-Protection (RASP) 相关报告*
9. 国家标准 GB/T 25070《信息安全技术 网络安全等级保护安全设计技术要求》
10. GB/T 22239《信息安全技术 网络安全等级保护基本要求》
11–15. 近三年中文核心期刊的 Web 攻击检测、RASP、AST 分析相关论文

> **重点**：第 6 篇 Buehrer 的 *Parse Tree Validation* 是"用语法树验证防注入"的经典工作。引用它并说明本方案的**改进之处**（结构指纹化 + 差分定位 + RASP 落地 + 可视化），能让创新点的学术定位非常清晰——这是答辩时"你的创新和已有工作有什么区别"这一问的标准答案。

## 7. 答辩预设问题与回答要点

| 预设问题 | 回答要点 |
|---|---|
| 正则 WAF 不是也能拦这些吗？ | 我不用正则。正则匹配的是文本形态，可被编码/注释/大小写混淆绕过；我匹配的是 AST 语义结构。TC-04 实验中 ModSecurity 被内联注释绕过，本系统全部命中。 |
| 为什么要做 RASP 层？网关不够吗？ | 网关只能看到 HTTP 参数，对"这个参数会不会造成注入"只能猜；RASP 拿到的是拼接完成的真实 SQL，是确定性判定。两层用 TraceID 关联形成完整证据链。 |
| 基线没学好会不会大量误报？ | 三重保障：基线命中直接放行不参与评分；新接口有学习期观察；Jaccard 相似度容差。且提供接口级豁免。第 7.5 节有误报率实测数据。 |
| 你这个和 OpenRASP 有什么区别？ | OpenRASP 主要做运行时钩子 + 规则判定；本系统的核心是结构指纹与差分定位，能精确指出"注入发生在语法树的哪个节点"，并将其可视化。这是检测粒度和可解释性的差异。 |
| 性能开销多大？ | 第 7.6 节实测：指纹缓存命中时 < 0.1ms，未命中 P95 < 5ms；正常流量因基线命中不触发差分计算，开销可忽略。 |
| 能防住 0day 吗？ | 对注入类攻击，只要它改变 SQL 语义结构就能被检出，不依赖已知特征，因此对未知变形有天然免疫力。但对不改变结构的攻击（如纯业务逻辑漏洞）无效——这在第 9.3 节局限性中有讨论。 |
| 一个人怎么完成这么多工作？ | 展示 Git 提交曲线与 14 天开发日志，说明每日进度与遇到的具体问题。 |
