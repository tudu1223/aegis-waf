### 1.2 非功能性需求

| 编号 | 指标 | 目标值 |
|---|---|---|
| NFR-01 | 检测延迟 | 单次 AST 检测 P95 < 5 ms |
| NFR-02 | 网关吞吐 | 单机 ≥ 500 QPS（本地演示环境） |
| NFR-03 | 误报率 | 正常业务流量误报率 < 1% |
| NFR-04 | 漏报率 | 对测试 payload 集漏报率 = 0% |
| NFR-05 | 大屏时延 | 攻击发生到大屏呈现 < 500 ms |

### 1.3 安全需求矩阵

| 安全属性 | 需求描述 | 实现手段 |
|---|---|---|
| 机密性 | 管理端凭据不以明文存储；日志脱敏 | BCrypt 加盐哈希；敏感字段掩码 |
| 完整性 | 安全事件日志不可篡改 | 哈希链（每条记录含前条哈希） |
| 可用性 | 抵御 CC 攻击；引擎故障不影响业务 | 限流 + 熔断降级 |
| 可认证性 | 管理端身份认证 | JWT（HS256，短时效 + 刷新） |
| 可授权性 | 管理端分级权限 | RBAC：ADMIN / ANALYST / VIEWER |
| 可审计性 | 全量操作留痕 | 审计日志表 + TraceID 全链路追踪 |
| 不可否认性 | 事件带时间戳与来源标识 | 事件签名与时序记录 |

### 2.2 STRIDE 威胁清单与缓解

| ID | 威胁类型 | 威胁描述 | DREAD 评分 | 等级 | 缓解措施 |
|---|---|---|---|---|---|
| T-01 | Tampering | SQL 注入篡改查询逻辑 | 9 | 严重 | AST 结构指纹 + RASP 确定性判定 + 参数化查询 |
| T-02 | Tampering | 存储型 XSS 注入脚本 | 8 | 高 | DOM 解析白名单净化 + CSP 响应头 |
| T-03 | Spoofing | JWT 伪造 / 篡改 | 8 | 高 | HS256 强密钥、短时效、算法白名单（拒绝 `none`） |
| T-04 | Elevation | 水平/垂直越权访问 | 8 | 高 | 资源属主校验 + RBAC 注解式鉴权 |
| T-05 | Info Disclosure | 路径穿越读取任意文件 | 7 | 高 | 路径规范化 + 根目录前缀强校验 |
| T-06 | Denial of Service | CC / 暴力破解 | 7 | 高 | 令牌桶 + 滑动窗口 + IP 信誉封禁 |
| T-07 | Tampering | 命令注入 | 9 | 严重 | 探针钩取执行点 + 参数数组化调用 |
| T-08 | Info Disclosure | 报错信息泄露栈与 SQL | 6 | 中 | 全局异常处理，统一错误响应 |
| T-09 | Repudiation | 攻击者否认攻击行为 | 5 | 中 | 哈希链日志 + TraceID 全链路 |
| T-10 | Info Disclosure | SSRF 探测内网 | 7 | 高 | 出站地址白名单 + 内网网段拒绝 |
| T-11 | Tampering | 不安全反序列化 | 8 | 高 | 禁用原生反序列化，仅用 JSON + 类型白名单 |
| T-12 | Spoofing | 检测绕过（编码混淆） | 8 | 高 | **多重归一化 + AST 结构判定（核心）** |

> DREAD 计分：Damage / Reproducibility / Exploitability / Affected users / Discoverability 各 0–10 取均值。≥7.0 视为高危，须在测试阶段给出修复证明。

## 7. 关键流程设计

### 7.1 请求检测主流程

```
① 请求进入网关
② TraceFilter 生成 TraceID，写入 MDC 与下游请求头 X-Sentinel-Trace
③ IpReputationFilter 查 IP 信誉 → 已封禁则直接 403
④ RateLimitFilter 令牌桶 + 滑动窗口 → 超限则 429 并累加风险分
⑤ DetectionFilter：
     5.1 提取全部参数（Query / Form / JSON Body / Header / Cookie）
     5.2 PayloadNormalizer 多重归一化
     5.3 RiskFeatureDetector 启发式预判 → 得到预判风险分
     5.4 若 ≥ 阻断阈值且策略为 BLOCK → 拦截并上报事件（不进入后端）
     5.5 否则放行，携带 TraceID 转发
⑥ 靶场应用处理请求，执行 SQL
⑦ RASP 探针钩住 Statement.execute，取得真实 SQL 与 TraceID
⑧ SqlFingerprintEngine 解析 AST → 归一化 → 计算指纹
⑨ 与该 endpoint 的基线指纹比对：
     命中  → PASS，hit_count++
     失配  → AstDiffer 计算结构差分，定位变异节点
              → 判定为注入 → 上报 CRITICAL 事件
              → 若策略为 BLOCK，探针抛出 SecurityException 阻断 SQL 执行 ★
⑩ 事件汇聚到控制台，写入哈希链日志
⑪ WebSocket 推送至大屏，AST 差分树实时渲染
```

> **第 ⑨ 步中的探针阻断是本方案的技术制高点**：在 SQL 真正送达数据库之前的最后一刻，基于确定性的结构判定拦下它。

### 7.2 基线学习流程

```
学习模式开启
  → 探针上报的每条 SQL 均计算指纹
  → 按 endpoint 归组，指纹入库，status = LEARNING
  → 学习窗口结束（或达到样本阈值 N=20）
  → 管理员在基线管理页审核，确认为 CONFIRMED
  → 切换至防护模式，未在基线中的指纹一律判定为异常
```

**冷启动兜底**：基线为空时不做"一律拦截"（会阻断正常业务），改为**纯风险特征判定**（恒真式、UNION 注入、堆叠查询、注释截断、时间盲注函数等），保证系统开箱即用。详见 `02-核心算法设计.md` 第 6 节。

## 9. 编码规范（对应指导书"关键安全逻辑须注释"的硬性要求）

### 9.1 安全注释规范

所有安全相关代码必须使用统一标记，便于报告中检索与展示：

```java
/**
 * [SEC-SQLI-01] SQL 注入语义检测
 * 
 * 安全原理：
 *   将 SQL 解析为抽象语法树后剥离全部字面量，得到仅反映"语法结构"
 *   的指纹。攻击者可以通过编码、注释、大小写等手段混淆文本形态，
 *   但注入攻击的本质是改变 SQL 的语义结构，而语义结构的改变必然
 *   导致 AST 变形，因此结构指纹必然失配。
 * 
 * 威胁对应：T-01 (STRIDE: Tampering, DREAD: 9.0)
 * 防护效果：对编码混淆类绕过手法免疫
 * 
 * @param sql       RASP 探针捕获的真实 SQL
```

### 9.2 高危函数禁用清单（指导书硬性要求）

| 语言 | 禁用项 | 本项目替代方案 |
|---|---|---|
| Java | `Runtime.exec(String)` 单字符串形式 | `ProcessBuilder(List<String>)` 参数数组化 |
| Java | `ObjectInputStream.readObject` | Jackson JSON + 类型白名单 |
| Java | 字符串拼接 SQL | `PreparedStatement` 参数化 |
| Java | `Class.forName` 动态加载用户输入 | 类名白名单校验 |
| Java | 直接使用 `Random` 生成安全令牌 | `SecureRandom` |
| 前端 | `v-html` 未净化内容 | 后端净化后输出 + `DOMPurify` 兜底 |
| 前端 | `eval` / `new Function` | 禁用 |

### 9.3 通用规范

- 包命名 `com.sentinel.<module>`，类名 UpperCamel，常量全大写下划线
- 所有 `public` 方法必须有 Javadoc
- 异常禁止吞掉，必须记录日志或向上抛出
- 检测引擎任何异常均降级为放行（可用性优先），并记录 `ENGINE_ERROR` 事件
- 单元测试覆盖 `sentinel-core` 全部检测算法，目标行覆盖率 ≥ 70%
