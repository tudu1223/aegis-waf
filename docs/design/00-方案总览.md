# AEGIS · 方案总览

> **课题全称**：基于 SQL 抽象语法树结构指纹的 Web 攻击语义检测与攻防可视化平台
> **英文名**：AEGIS — Semantic Engine for Network Threat Interception & Erroneous-Logic Neutralization
> **对应指导书题目**：自拟题目（融合第 10 题 Web 应用防火墙、第 24 题网络入侵检测系统、第 4 题安全在线笔记系统）
> **技术难度**：★★★★☆
> **完成形式**：小组协作完成（组长：黄思凯；组员：罗锦皓、曾铭、吴靖翔）

## 1. 一句话定位

**不做正则匹配的 WAF，做一个真正"看得懂 SQL 语义"的 WAF。**

传统 WAF 用黑名单正则匹配攻击特征串，本质上是在**猜**一段文本像不像攻击，因此永远处于"新绕过手法出现 → 补规则 → 再被绕过"的被动循环。

AEGIS 换一个维度解决问题：把 SQL 解析成**抽象语法树（AST）**，剥离全部字面量后计算**结构指纹**，与该接口的合法基线指纹比对。攻击者无论使用何种编码、注释、大小写、内联注释混淆，只要他**改变了 SQL 的语义结构**，AST 就必然变形，指纹就必然失配。

> 这句话是本课题应对答辩提问的核心武器：
> **问**："正则规则不是很容易被绕过吗？"
> **答**："我根本不用正则。攻击者可以混淆文本，但无法在不改变语法树的前提下改变 SQL 的语义——而改变语义正是注入攻击的目的本身。"

## 2. 核心创新点（四条，按含金量排序）

### 创新点 1：SQL 抽象语法树结构指纹（AST Structural Fingerprint）

将 SQL 语句解析为语法树，执行**字面量归一化**（所有常量→占位符）与**规范化序列化**，得到唯一结构指纹。检测过程是**确定性的结构同构判定**，而非概率性的特征匹配。

对比业界：ModSecurity 属于正则规则集；libinjection 属于 SQL 词法状态机（只看 token 序列，不构建完整语法树）。本系统构建**完整语法树并做结构差分定位**，能精确指出"攻击载荷注入在语法树的哪个节点"——这是可视化演示的数据基础。

### 创新点 2：网关 + RASP 探针双层联动架构 ⭐ 最具区分度

这是整个方案技术格调的来源。

| | 网关层（Gateway） | RASP 探针层（Agent） |
|---|---|---|
| 位置 | HTTP 流量入口，反向代理 | 应用进程内部，Java Agent 字节码注入 |
| 可见对象 | HTTP 参数（原始文本） | **最终拼接完成的真实 SQL** |
| 判定性质 | 启发式预判（有误报可能） | **确定性判定（零猜测）** |
| 作用 | 快速拦截、限流、粗筛 | 精确取证、结构指纹比对 |

**为什么这一步是关键**：网关层看到参数 `id=42 OR 1=1`，它只能猜这像不像攻击；而 RASP 探针钩住 JDBC 的 `Statement.execute()`，拿到的是**已经拼接完成、即将送入数据库的那条真实 SQL**，此时做 AST 比对是**确定性证明**——不存在"像不像"的问题，只有"结构变没变"。

两层通过同一个 **TraceID** 串联，可在大屏上还原完整证据链：

```
HTTP 请求 → 哪个参数被污染 → 生成了什么 SQL → AST 在哪个节点变异 → 判定与处置
```

本科课程设计中实现 RASP 层的极少，这是与其他小组拉开代差的核心。

### 创新点 3：无正则的 XSS 语义净化

同样拒绝正则。使用 HTML 解析器构建 DOM 树，基于**标签/属性/协议三级白名单**做净化，并对 `javascript:` 伪协议、`on*` 事件属性、`<svg>/<math>` 命名空间混淆、HTML 实体多重编码等绕过手法做规范化解码后判定。与"正则过滤 `<script>`"这类做法形成鲜明的技术层次对比。

### 创新点 4：攻防对抗实时可视化

将检测过程中产生的 AST 差分结果**实时渲染为可视化语法树**：合法结构显示为青色，注入产生的变异子树高亮为红色并带脉冲动效。攻击发生的瞬间，大屏上"红色子树破土而出"——这是任何 PPT 都无法替代的演示效果。

## 4. 模块清单

| 模块 | 形态 | 职责 | 关键技术 |
|---|---|---|---|
| `sentinel-core` | Java 库 | 检测算法内核：AST 解析、归一化、指纹、差分、风险特征、XSS 净化 | JSqlParser、jsoup |
| `sentinel-agent` | Java Agent | RASP 探针，字节码注入钩取 JDBC / 文件 / 命令执行 | ByteBuddy、Instrumentation |
| `sentinel-gateway` | Spring Boot | 反向代理 + HTTP 层检测 + 限流 + 拦截 | Servlet Filter、Caffeine |
| `sentinel-console` | Spring Boot | 事件汇聚、基线管理、WebSocket 推送、统计、导出 | Spring Boot 3、H2/MySQL |
| `sentinel-web` | Vue 3 | 指挥中心前端 | Vue3 + TS + Vite + G6 + ECharts |
| `vuln-target` | Spring Boot | 靶场：故意留洞的在线笔记系统 | 含 10 类可控漏洞 |

## 5. 演示脚本（验收现场的 8 分钟）

这套流程是按"评分表能拿到分"倒推设计的，务必按此排练。

| 时间 | 动作 | 展示的评分点 |
|---|---|---|
| 0:00–0:30 | 打开指挥中心大屏，系统全绿，正常业务流量平稳滚动 | 界面美观（10%） |
| 0:30–1:30 | **关闭防护**，演示经典注入 `' OR '1'='1` 直接登录成功，脱库 | 漏洞真实存在 |
| 1:30–2:30 | **开启防护**，同一 payload 被拦截；大屏 AST 树上红色 `OR` 子树弹出 | 核心创新 + 震撼点 |
| 2:30–4:00 | 连续打出 8 种混淆变形（内联注释、编码、大小写、`UNION`、盲注 `SLEEP`、堆叠查询），**全部拦截** | 证明非正则的优越性 |
| 4:00–5:00 | 点开任一事件，展示 TraceID 串起的完整证据链：HTTP 参数 → 真实 SQL → AST 差分 | RASP 双层架构 |
| 5:00–6:00 | 存储型 XSS 演示：`<img src=x onerror=alert(1)>` 与 `<svg/onload=>` 变形均被净化 | XSS 语义净化 |
| 6:00–7:00 | CC 攻击压测，限流曲线实时飙升并触发封禁；攻击者 IP 画像亮起 | 防护完整性 |
| 7:00–8:00 | 打开"漏洞修复对比"页，展示 10 个 OWASP 用例修复前后对照 | 硬性要求闭环 |

## 7. 团队协作与过程留痕

评分表中"团队合作 10%"与"管理文档 5%"需要**过程留痕**支撑：

1. **Git 全程留痕**：从第一天起建仓，**每日至少 2 次有意义的提交**，提交信息遵循 Conventional Commits（`feat:` / `fix:` / `docs:` / `test:`）。答辩时展示提交曲线，即是最硬的过程证据。
2. **开发日志**：`docs/journal/` 下按日建 md，记录当日目标、产出、遇到的问题与解决思路、次日计划。这直接对应"管理文档完整翔实"。
3. **甘特图 + 燃尽图**：将两周计划绘成甘特图放进报告"项目管理"章节，用实际提交数据画燃尽图，体现进度控制。
4. **个人总结与心得**：评分表明确列出（5%），单独成章，写清技术难点突破过程与安全观认识。
5. **自我角色划分**：在管理文档中以"需求分析师 / 架构师 / 开发工程师 / 安全测试工程师"四个角色视角记录工作，体现完整软件工程流程认知。
